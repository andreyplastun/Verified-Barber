ЗАДАНИЕ АГЕНТУ

Название: Исправить scheduler отправки WhatsApp сообщений (Rateus → AssistBot)

Цель  
Система должна стабильно отправлять сообщения с magic link после визита, учитывая:

• прогрев WhatsApp (лимит сообщений в день)  
• тихие часы 20:00–10:30  
• задержку первого сообщения 45–75 минут после визита  
• follow-up через 21–24 часа  
• приоритет follow-up  
• отсутствие остановки очереди

Нужно переписать scheduler, чтобы сообщения никогда не «зависали» и очередь не останавливалась.

────────────────

1. УБРАТЬ dynamic gap

Удалить из кода:

• dynamicGap  
• remainingWindow  
• spreadAcrossWindow  
• распределение сообщений по дню  

Эта логика не нужна.

Сообщения должны отправляться по scheduledAt.

────────────────

2. СТРУКТУРА СООБЩЕНИЯ

Каждое сообщение должно иметь поля:

type  
(primary | followup)

scheduledAt  
timestamp когда сообщение можно отправить

visitId

priority  
followup = 1  
primary = 2

status  
pending  
sent  
failed

────────────────

3. СОЗДАНИЕ СООБЩЕНИЙ

После завершения визита создаём PRIMARY сообщение.

scheduledAt:

visitCompletedAt + random(45–75 минут)

type = primary  
priority = 2

После создания PRIMARY автоматически создаём FOLLOWUP:

scheduledAt:

visitCompletedAt + random(21–24 часа)

type = followup  
priority = 1

────────────────

4. ТИХИЕ ЧАСЫ

Тихие часы:

20:00 — 10:30

Если scheduledAt попадает в тихие часы:

перенести scheduledAt на 10:30 следующего дня.

────────────────

5. ЛИМИТ ПРОГРЕВА

Используем dailyLimit.

Пример:

Day1 = 2  
Day2 = 3  
Day3 = 5  
Day4 = 8  
Day5 = 12  
Day6+ = 15+

Важно:

если лимит достигнут — очередь НЕ останавливать.

Нельзя использовать:

return

Нужно просто не отправлять новые сообщения.

────────────────

6. RESET СЧЁТЧИКА

Каждый день в 00:00:

sentToday = 0

Без этого система может зависнуть.

────────────────

7. ОЧЕРЕДЬ ОТПРАВКИ

Каждую минуту scheduler должен:

1. проверить quiet hours  
2. проверить dailyLimit  
3. выбрать сообщения где

status = pending  
scheduledAt <= now

4. сортировать:

priority ASC  
scheduledAt ASC

Это значит:

followup всегда отправляется раньше primary.

────────────────

8. ОТПРАВКА

При отправке:

POST AssistBot API

с параметрами:

destination_params.phone  
text  
salon  
type = whatsapp

Сохранить:

assistbot_message_id  
status = sent  
sent_at

sentToday++

────────────────

9. ИНТЕРВАЛ МЕЖДУ СООБЩЕНИЯМИ

Минимальный интервал:

random(10–15 минут)

НО:

если очередь пустая — ждать нечего.

────────────────

10. ЗАЩИТА ОТ ЗАВИСАНИЯ

Scheduler НИКОГДА не должен завершаться через return.

Он должен работать постоянно.

Если лимит достигнут:

просто ждать следующего дня.

────────────────

11. ОЧИСТКА ОЧЕРЕДИ

Добавить защиту:

если сообщение pending > 7 дней  
→ пометить expired

чтобы очередь не разрасталась.

────────────────

12. ЛОГИРОВАНИЕ

Логировать:

• visitId  
• тип сообщения  
• scheduledAt  
• sent_at  
• assistbot_message_id  
• ошибки отправки

────────────────

РЕЗУЛЬТАТ

Система должна:

• отправлять primary через ~1 час после визита  
• отправлять follow-up через ~1 день  
• соблюдать лимит прогрева  
• соблюдать тихие часы  
• никогда не зависать  
• отдавать приоритет follow-up
