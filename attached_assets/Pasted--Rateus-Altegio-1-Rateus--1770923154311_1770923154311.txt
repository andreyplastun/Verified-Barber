ТЗ агенту: Синхронизация Rateus → Altegio

1. Цель

При создании или изменении визита в Rateus
→ автоматически создавать / обновлять запись в Altegio.

Rateus становится источником записи, Altegio — зеркалом.
2. Условие активации

Синхронизация работает только если у специалиста:

✔ подключён Altegio
✔ сохранён altegio_user_id / altegio_staff_id

Если нет подключения → логика не вызывается.

⸻

3. События, которые триггерят синхронизацию

В Rateus:

✔ визит создан (Scheduled)
✔ визит изменён (дата / время)
✔ визит отменён
✔ визит завершён (Completed)

4. Endpoint Altegio

Агент использует API Altegio:

Создание записи:

POST /appointments

Обновление:

PUT /appointments/{id}

Отмена:

DELETE /appointments/{id}

(реальные маршруты сверить с Altegio API)

⸻

5. Создание визита → Altegio

Если визит создан в Rateus:

→ вызвать Altegio API
→ создать запись

Передать:

✔ staff_id (мастер)
✔ client_name
✔ client_phone
✔ datetime
✔ comment (если есть)

⸻

6. Сохранение связки

После успешного ответа Altegio:

→ сохранить в визите Rateus:

altegio_appointment_id

7. Обновление визита

Если меняется дата / время:

→ PUT в Altegio
→ обновить запись

Если altegio_appointment_id == null:

→ создать новую запись

⸻

8. Отмена визита

В Rateus → статус Cancelled

Если есть altegio_appointment_id:

→ DELETE / cancel в Altegio

⸻

9. Завершение визита

В Rateus → статус Completed

Если визит пришёл из Rateus:

→ обновить статус в Altegio → completed

Если Altegio уже completed → ничего не делать.

⸻

10. Защита от циклов

Важно избежать петли:

Rateus → Altegio → webhook → Rateus → Altegio…

Решение:

Добавить флаг источника:

updated_from = rateus | altegio
Если изменение пришло из webhook Altegio:

→ НЕ отправлять обратно в Altegio.

⸻

11. Обработка ошибок

Если Altegio API вернул ошибку:

✔ визит в Rateus остаётся
✔ показать лог в системе
✔ retry (опционально)

⸻

12. Retry логика (опционально)

При сетевой ошибке:

→ повторить через 5 / 15 / 60 минут

Максимум 3 попытки.

⸻

13. UI статус синхронизации

В визите Rateus:

Показывать индикатор:

✔ «Синхронизировано с Altegio»
❌ «Ошибка синхронизации»

⸻

14. Логирование

Логировать:

✔ действие (create/update/cancel/complete)
✔ altegio_appointment_id
✔ ответ API

⸻

15. Тесты

Проверить:

✔ создание визита → запись в Altegio
✔ изменение времени → обновление
✔ отмена → отменяется в Altegio
✔ завершение → закрывается

✔ webhook Altegio не вызывает повторный Rateus → Altegio

⸻

16. Результат

После внедрения:

✔ клиент может записаться через Rateus
✔ запись появляется в Altegio
✔ статусы едины
✔ дублей нет
✔ циклов нет
